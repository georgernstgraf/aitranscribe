# Pitfalls

Things that do not work, subtle bugs, and non-obvious constraints.
Read this file carefully before making changes in affected areas.

- **CRITICAL**: Skills resolve via the global opencode config (`~/.config/opencode/skills`, itself a symlink into the `opencode-helpers` repo) through the `skill` tool. There is NO repo-local `skills/` directory (the old gitignored symlink was removed 2026-09-21). OpenClaw bundled skills (github, gh-issues, weather, etc.) are FORBIDDEN despite appearing in `available_skills`.
- Setting the user's terminal title from inside opencode does NOT work by printing the OSC sequence to stdout — opencode pipes the shell output, so the escape code never reaches the terminal. Working method: find the opencode PID whose cwd matches the repo (`ls -l /proc/<pid>/cwd` for each opencode PID from `ps -eo pid,tty,cmd | grep opencode`), map it to its pts device, then write directly: `printf '\033]2;<title>\007' > /dev/pts/N`. Verified working on gnome-terminal (VTE) under Wayland.
- Do not pass Markdown backticks unescaped inside `gh issue create --body "..."`; the shell will treat them as command substitution.
- `runner.invoke(app, [])` does not preserve a reliable `sys.argv` shape for default-mode detection, so default TUI launch logic must be inferred from parsed option values instead.
- Typer evaluates `main()` signature defaults at import time. Any option default that depends on initialized state must be `None` at import and resolved inside `main()` after `init_app()`; a direct global default (e.g. `typer.Option(GROQ_STT_MODEL, ...)`) silently bakes in `None`.
- Textual 8.x `Focus`/`Blur` events do NOT bubble — an app-level `on_blur` never fires for Input blur. To react to widget blur, subclass the widget and post a custom bubbling Message from its `on_blur` (see `PersistInput` in tui.py).
- When replacing a test function via Edit, include the next test's `def` line in BOTH oldString and newString — replacing only the `def` line deletes the following function header (happened twice with `test_wrap_text_short`).
- `typer.Exit` inherits from `Exception` (via `click.exceptions.Exit`). An `except Exception` around a block that raises `typer.Exit` converts clean exits into error exits — catch specific errors instead.
- `main.init_app()` mutates a dozen module globals. Tests calling it directly must snapshot/restore `_INIT_GLOBALS` (see `tests/test_cli.py`) or later tests fail with `KeyError` on `PROMPTS` subkeys.
- Manual testing of `main.py` default startup still requires a real terminal and microphone access; automated tests only cover the non-interactive seams.
- A fullscreen terminal UI built on the current library does not satisfy the requirement that transcript text must remain mouse-selectable for copy/paste into other applications.
- Visible mouse highlighting inside the current `Textual` TUI can still fail to populate either `PRIMARY` or `CLIPBOARD`, even when tested in `kitty`; terminal choice alone is not a reliable fix.
- Compact `Switch` widgets in the sidebar rendered badly and were not practically usable; `Checkbox` is the safer control for these boolean settings.
- Clipboard helpers may be missing from the environment; `xclip` / `wl-copy` availability materially changes whether explicit copy works without falling back to OSC52.
- TUI model and file-path inputs now persist through `Input` events, so avoid persisting empty model values and expect the config file to change during typing.
- The filesystem-file path is transcribed from the `file_path` input submission path; pressing `Space` should remain microphone-only behavior.
- A forced `height: 1` override on `Textual` `Input` widgets can break practical text entry; keep file-path entry using the default input behavior.
- When using `gh issue create` or `gh issue comment` from Bash, do not put backticks inside a double-quoted `--body`; the shell will execute them unless you use a heredoc or otherwise escape them.
- Never pass a pre-existing file under `/tmp/opencode/` to `gh issue create --body-file` without reading it first; stale files from other sessions get silently attached as the issue body. Always verify with `gh issue view` after creating.
- Never `rm -rf <path>/` with a trailing slash before running `readlink`/`ls -la` on it: on a symlink-to-directory the trailing slash follows the link and wipes the TARGET's contents (2026-09-21: emptied `opencode-helpers/skills/`, recovered via `git checkout`). Likewise, `diff -rq a/ b/` is vacuous when both paths resolve to the same directory — always compare canonical paths first.
- `OptionList.size.width` can be misleading on the initial TUI render; use live content-region widths with a fallback to avoid premature ellipses in history rows at startup.
- The sidebar height bug was not caused by the outer sidebar container; the real fix is to make `#history_panel` itself `1fr` and leave `Recording Mode` and `Configuration` at fixed/auto heights.
- Mouse-driven focus changes in the `Textual` TUI can leave the visible mode indicator stale unless focus-change events explicitly refresh the state field.
- Do not use the editor contents as the append base for saved transcriptions; stale pane text can diverge from the selected DB entry even when persistence still targets the correct prompt id.
- Never silently swallow exceptions with `pass` or bare `return` in `except` blocks. Every caught exception must be user-visible via `ErrorDialog` (TUI) or `console.print` (CLI). Silent failures cascade into confusing errors like `AssertionError` with no context (`main.py:753` pattern).
- `core.py`'s `compress_audio` and `chunk_audio` previously silently fell back on ffmpeg failure. They now propagate exceptions — callers must handle them explicitly. If you add a new library function that may fail due to missing system dependencies, propagate the exception rather than catching silently.
- `core.py`'s `chunk_audio` derives segment length from bitrate (duration via ffprobe + file size, 5% margin, 60s floor) and the upload ceiling (`GROQ_MAX_UPLOAD_S = 120`, default `max_duration_s`), NOT from a fixed value. Tests of it must patch `core.get_audio_duration`, `core._silence_midpoints` (otherwise real ffmpeg runs silencedetect on the fixture) and optionally `core.os.path.getsize`; cut points reach ffmpeg as `-segment_times t1,t2,...` (list form, snapped into pauses by `_snap_cut_points`) and only fall back to the classic `-segment_time N` when no cut point fits. `compress_audio` raises if ffmpeg produced no non-empty output; `transcribe_audio` raises `FileNotFoundError` for missing files — tests must create the output file inside the patched `_ffmpeg` scope (before the `compress_audio` call, not after).
- `_DEFAULT_PROMPTS_TOML` is the source of truth for initial `prompts.toml` creation. Any structural change to the prompts file (new keys, renamed sections) must also update this embedded default string in `main.py`.
- Changing a prompt *default value* additionally requires extending the `_LEGACY_*` upgrade path in `_load_prompts()` (`_upgrade_legacy_prompt_defaults`), or existing installs silently keep the old text — new defaults only reach fresh `prompts.toml` files otherwise.
- `[post_process].system` and `[system]` are different prompts for different call sites: post-process uses `[post_process].system` (dictation-cleanup rules ending in "Return only the cleaned-up transcription"), while summary and standalone translate still use the generic `[system]` prompt. Wiring a new LLM call to the wrong one produces contradicting instructions.
- `transcribe_audio` now returns a `(text, language)` tuple from `verbose_json`, not a bare string. Existing mocks/patches of it must return tuples or unpacking in `run_transcription_pipeline` breaks.
- The config file is `~/.config/aitranscribe/config.toml` (schema v2). A legacy `aitranscribe.conf` **is** migrated automatically on first start (values mapped, duplicate blocks collapsed, file moved to `aitranscribe.conf.bak-<timestamp>`); the even older `~/.config/aitranscribe/config` file is still not detected — copy its keys manually if a machine only has that one.
- Textual's default `AUTO_FOCUS` focuses the first focusable widget during mount, which (a) starts the app in Pane Focus Mode and (b) fires app-level `on_descendant_focus` → `refresh_status()` before the status panel is queryable in some mount orders, crashing tests with `NoMatches: '#state_status'`. `AitranscribeTUI.AUTO_FOCUS = None` prevents both; never reintroduce automatic focus-on-mount.
- TUI tests that assert Pane-Focus-Mode status text must explicitly `set_focus(...)` a pane widget — nothing is focused at mount anymore (startup test at `test_tui.py::test_tui_starts_in_command_mode_on_mount` pins the Command Mode contract).
- When embedding TOML content in a Python triple-quoted string, avoid using `r'''\` (raw string with trailing backslash) — the backslash becomes literal and creates invalid TOML output. Use `"""\` (regular string with line-continuation backslash) instead.
- `tomllib` is stdlib in Python 3.11+ but missing in older versions. The project's pyproject.toml requires `>=3.10`, but the prompts.toml feature effectively requires 3.11+ unless a compatibility shim is added.
- In the Textual TUI, `refresh_history()` re-renders the editor via `select_history_prompt` — both directly AND indirectly through the `OptionHighlighted` event handler (setting `highlighted` after `set_options` fires the event). Any code path that must not clobber user edits (e.g. background summary completion) must use `apply_summary_to_history()` instead, which only replaces a single option's prompt text.
- Headless `pytest` runs fail at `from pynput import keyboard` (no X connection). The desktop session's sockets work only with its auth cookie: `XAUTHORITY=/run/user/1000/.mutter-Xwaylandauth.* DISPLAY=:0 venv/bin/pytest tests/`. `~/.Xauthority` and bare `DISPLAY` do not work.
- On hosts with no X session at all (agent containers), `xvfb-run -a ./venv/bin/pytest tests/` works instead (`Xvfb` binary + `pip install -r requirements.txt -r requirements-dev.txt`; `libportaudio2` via apt for sounddevice). Full suite verified green this way except pre-existing env failures (see next).
- Groq STT silently truncates very long single uploads: a 43-min/24 MB Zoom file in one request lost the last minute (mid-sentence cutoff). `chunk_audio` therefore also splits by duration — size-only chunking is not enough — and the duration ceiling is now `GROQ_MAX_UPLOAD_S = 120` (was 600), see the 2026-10-18 entry below.
- Leading silence in recordings (e.g. ~8 quiet minutes before a Zoom meeting starts) transcribes as repeated "Thank you." Whisper hallucinations. The cleanup prompt removes only trailing ones; raw mode keeps them verbatim.
- English-mode post-processing with `gpt-oss-120b` restructures into meeting minutes (headers, tables) and may relocate passages (a mid-meeting farewell became the "Closing" section). Raw mode is the verbatim record.
- `test_cli_file_missing_arg` depends on a valid `GROQ_API_KEY` in the real `~/.config/aitranscribe/aitranscribe.conf` (the autouse `init_app` fixture loads real config, and key validation runs before the file check). On hosts without keys it fails with "GROQ_API_KEY is not set" instead of "File not found" — pre-existing environmental failure, unrelated to prompt changes (verified identical on unmodified baseline).
- System Python upgraded to 3.14 (Ubuntu) WITHOUT `python3.14-venv`/`python3.12-dev` packages: `python3 -m venv` fails (ensurepip missing) and `python3.12 -m venv` builds a venv that cannot compile C extensions (`evdev` from pynput fails: no Python.h for 3.12). Working recipe (no sudo): `python3 -m venv --without-pip venv` → `./venv/bin/python get-pip.py` → pip install (3.14 has dev headers at /usr/include/python3.14 and wheels for all requirements). System pip is PEP 668 externally-managed, but venv-created pip is unaffected.
- Running `./aitranscribe` from an SSH/headless session on dell fails at import (`pynput` needs X). Use the graphical session's Xwayland: `DISPLAY=:0 XAUTHORITY=/run/user/1001/.mutter-Xwaylandauth.<SUFFIX> ./aitranscribe ...` (auth file name is per-session, find via `ps aux | grep Xwayland`). Tests need the same env vars.
- **Historical, fixed by schema v2**: the dotenv migration appended a block whenever a key was missing, but commented-out keys are invisible to `dotenv_values` — every start appended again (owner file: 118 duplicated Cohere blocks in 511 lines, the reason the format was replaced). Never reintroduce an append-on-start migration; `config.migrate_if_needed()` runs once (only when `config.toml` is absent) and moves the legacy file to `.bak-<timestamp>`.
- When `_DEFAULT_PROMPTS_TOML` changes structurally (e.g. new `[post_process.system]`), an existing user `prompts.toml` must be updated manually — `_validate_prompts` then exits with `SystemExit(1)` on EVERY CLI invocation AND breaks the entire test suite at collection (test fixtures load the user's real config). Symptom: dozens of `ERROR tests/...::test_x` fixtures with "Missing required prompt key".
- A quoted path pasted into the TUI file input reaches `os.path.exists()` with literal quote characters unless normalized. `normalize_file_path()` removes only a matching outer quote pair; the same helper serves the CLI file path.
- On Windows, missing `ffprobe` was swallowed by `chunk_audio()` and shown as misleading `invalid duration (0.0s)` for large files. FFmpeg must be installed with `ffprobe` and the terminal restarted after WinGet changes PATH.
- An `.mp3` filename can contain an MP4 video container. The reported 2.36 GiB interview file has H.264 video plus AAC audio; size-based chunking of the original would exceed STT upload limits. Large filesystem inputs are converted directly to 32 kbps audio before chunking.
- In `chunk_audio()`, if `get_audio_duration()` fails and the file is under `max_size_mb`, the file is returned unsplit. For a small-but-long file with a broken `ffprobe` (but working ffmpeg) this silently skips duration chunking — the narrow case where the STT-truncation bug can reappear.
- On Windows, several existing `tests/test_cli.py` cases leave SQLite connections open and fail in cleanup with `PermissionError: [WinError 32]` when unlinking temporary databases. These failures are independent of file-path handling.
- `wrap_text()` reads the module global `OUTPUT_WIDTH` (set by `init_app()`, default 80). It is line-preserving: it wraps only lines longer than the width and never joins existing line breaks, so it is idempotent. Consequence: changing `OUTPUT_WIDTH` does NOT reflow already-wrapped stored text — do not "fix" this by reflowing paragraphs, that destroys markdown/list structure (see DECISIONS 2026-09-27).
- **Historical (pre-v2, no longer applicable)**: `persist_config_value` bound `config_file=CONFIG_FILE` at import time so tests wrote into the real config. Since schema v2 all writes go through `config.set_value(CONFIG_FILE, ...)` and read `CONFIG_FILE` at call time; patch `main.CONFIG_FILE` (or `main.config.set_value`) in tests, never the user's live file.
- `PromptManager.add_prompt`/`update_prompt` wrap text via `wrap_text()` using the global `OUTPUT_WIDTH`, so stored transcripts are normalized at the storage boundary. Tests that assert exact stored text must therefore use short (<width) strings or reset `main.OUTPUT_WIDTH`.
- **Historical (pre-v2)**: `_create_default_config`/`_MIGRATION_BLOCKS` appended `OUTPUT_WIDTH` and provider blocks to the dotenv file. Both are gone with schema v2 (`_create_default_config` now delegates to `config.create_default`); new UI settings must be added to `config.render_document()` and to `_apply_app_config()` instead.
- GitHub closes an open pull request when its head branch is renamed. Open a replacement PR from the renamed branch and update references to the old PR.
- On hosts without `Xvfb`/`xvfb-run`, headless pytest can run with `PYNPUT_BACKEND=dummy` (prevents the `from pynput import keyboard` import from failing on a missing X connection). Verified 2026-09-27: `PYNPUT_BACKEND=dummy ./venv/bin/pytest -q` → 186 passed, 1 skipped.
- **Groq mangles the transcript of uploads longer than ~120 s: every word loses its tail from the first non-ASCII character on** (`würde`→`w`, `natürlich`→`nat`, `möchte`→`m`, `Stärke`→`St`, `ähnliches`→gone, `ki-strategie.bmb.gv.at`→`ki`), which is why German umlaut words looked "cut off at the letter before the umlaut". Measured 2026-10-18 against `whisper-large-v3` and `-turbo` on the owner's own recordings: **≤120 s uploads byte-identical to `words[]`, ≥122 s mangled** (122 s barely, 124 s+ clearly; 134–394 s recordings all mangled), the same 120 s trim of the same file clean, and a 20 s excerpt around the broken passage clean. It is server-side (the raw HTTP bytes contain the truncated text), it hits `text` *and* `segments[].text`, and **no request parameter avoids it** (`text`/`json`/`verbose_json`, `prompt`, `language`, `temperature=0`, both models). **`words[]` (requested via `timestamp_granularities: ["word"]`) stays correct in mangled responses**, and joining `words[]` reproduces `text` byte-for-byte when the service is healthy (verified on three clean recordings) — that is what `core.transcribe_audio` now returns, with `text` as the fallback for models that reject the parameter. Second defence: `chunk_audio(max_duration_s=GROQ_MAX_UPLOAD_S=120)` + the recording path passing `do_chunk=True`, so no upload exceeds the broken range either. Do NOT "simplify" `transcribe_audio` back to `transcript.text` — it silently reintroduces the bug. Chunk cut points are snapped into silencedetect pauses (`_snap_cut_points`), because a seam inside a word truncates that word just like the Groq bug does. Symptom owner-visibility: dictations under 2 minutes were always fine, which is why the bug looked intermittent.
- A suspended PipeWire input source can deliver **zero callbacks** to `sounddevice` at 44.1 kHz even though the device works: measured 2026-10-25 with the OBSBOT Meet SE webcam mic (PipeWire node, native 32 kHz) — 0 frames in 2-3 s (once 1 frame/384 samples), while 32 kHz/48 kHz and the internal ALC233 delivered ~115 frames/s. The same broken stream makes `stream.stop()` block **6.8–25 s**, and because `RecordingController.stop()` runs on the Textual event loop the TUI froze on `Recording` and finally said "No audio recorded". The workaround for users is switching the system default input; the app now protects itself, so do NOT remove `_close_stream_bounded()` (daemon thread + `abort()` fallback, bounded by `STREAM_STOP_TIMEOUT_S`) or the `schedule_audio_probe()`/`check_audio_input()` watchdog without keeping an equivalent bound — a plain `stream.stop()` in the UI thread reintroduces the freeze.
- `RecordingController.frames_captured` counts callbacks that were actually appended (so it stays 0 while paused by design); the audio watchdog skips paused recordings for that reason and must keep doing so, otherwise `P` followed by the 2 s probe aborts a perfectly healthy take.
- The watchdog timer is scheduled via `self.set_timer()`, which needs a running app: `schedule_audio_probe()` returns early when `self.is_running` is False, because several tests call `app.start_recording()` outside `run_test()` and would otherwise crash with `RuntimeError: no running event loop`.
- PortAudio's *default* input on Linux is ALSA's `default` PCM — which is the PipeWire/PulseAudio ALSA plugin. It floods stderr with `Expression '...' failed in 'src/hostapi/alsa/pa_linux_alsa.c'` assertions, reports a phantom 128-channel device and blocks `Pa_StopStream` for 6-25 s on a suspended node (2026-10-25, measured on think with PipeWire 1.6.2). `tui.resolve_input_device()` therefore prefers the native `PulseAudio`/`PipeWire` host API's `default_input_device`; measured 2300-3600 frames/2.5 s with `stop()+close()` in 0.02 s and **zero** stderr lines, while the ALSA plugin path delivered 0-231 frames with up to 25 s close. Do NOT remove the host-API preference or "simplify" it back to `InputStream(device=None)`.
- PortAudio device indices are not stable across replug/session changes (the webcam adds devices 1/27). `RecordingController.start()` re-resolves the index on every take, so never cache it across recordings.

- **Config schema v2 (TOML)**: the scope tables `[stt]`/`[llm]` must contain the selector (`provider`) and nothing else. Adding e.g. a scope-level `model` recreates the override/default split that made the dotenv file unmaintainable (`--stt-model` is the ad-hoc path).
- Rich's `console.print` interprets `[...]` as markup, so printing a profile reference like `[stt] selfhosted-1` silently drops the bracket text (observed: `✓  selfhosted-1: …`). Pass `markup=False` for config diagnostics that print TOML paths; tests asserting those strings will otherwise fail.
- Textual `Select` needs `(label, value)` tuples or `SelectOption`; reading provider maps from `initial_settings["stt_providers"]` (filled by `main.get_tui_settings`) is the single source for the model-per-provider map. The `Select.Changed` handler fires once on mount, so it must return early when `event.value == self.<scope>_provider` — otherwise it persists on every launch and overwrites the status line.
- Programmatic `Select.value` assignment raises `InvalidSelectValueError` for values not in the option list; tests that set it must use a profile name that exists in the map they passed.
- The active STT profile's `max_upload_s` is what reaches `chunk_audio` (via `main._chunk_with_active_profile`). A test that patches `main.chunk_audio` with `lambda f: [f]` breaks as soon as kwargs are passed — accept `**kwargs`.
- `tomlkit` writes a new table at the end of the document, so `config.set_value(..., "stt", "providers", "<new>", ...)` appends the profile after `[paths]`. Valid TOML, but for a clean layout add the profile block by hand (the owner's config has the self-hosted block above `[llm]`).
- Tests that call `main.get_tui_settings()`/`persist_tui_setting()` must create a real `config.toml` in `tmp_path` and patch `main.CONFIG_FILE`; `get_tui_settings` reloads from the file (no reliance on the `CONFIG` global), precisely so a stale global from an earlier test cannot leak settings.
